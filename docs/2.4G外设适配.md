# 2.4G 外设适配

在「资源胶囊设置 → 资源与阈值 → 外设电量」扫描并选中 USB 接收器接口。诊断 JSON 包含 VID、PID、HID Usage Page、Usage 和报文长度等匹配信息。要读取电量，还需要厂商协议资料、可参考的实现，或有实际读数可对照的报文样本。

1. 用「更多操作 → 导出扫描诊断与提示词」保存诊断和 Agent 提示词。
2. 选中对应的厂商接口，点「采集电量报文样本」。读取 Feature 报告需要已知的报告 ID。设备会主动上报时，可先用 Input 报告的「任意 ID」采样。记录厂商软件显示的电量和充电状态，采集后点「导出上次报文样本」。有条件时在不同电量或充电状态下各保存一份。
3. 把诊断、提示词和样本或协议资料交给 Agent，要求生成 `peripheral-profiles.json`。回到向导导入并试读，对照厂商软件确认后保存。

采样只针对选中的厂商自定义 HID 接口，短时间读取少量报文。样本文件会包含该接口返回的原始字节，请在分享前核对内容。设备超时、没有上报或接收器断开时，不能把它推断为休眠或 0%。

## 配置格式

版本 1 配置继续适用于已有的内置协议。版本 2 可以使用 `custom-read`，描述读取方式、报告 ID、报文特征、电量字段和可选的状态字段。配置仍需要与当前电脑扫描到的接收器指纹精确匹配。

下面是格式示例。设备标识、字段位置和值均为演示，实际文件应按目标设备的资料填写。

```json
{
  "format": "bigfishdock-peripherals",
  "version": 2,
  "profiles": [
    {
      "vid": 4660,
      "pid": 22136,
      "usage_page": 65280,
      "usage": 1,
      "input": 8,
      "output": 0,
      "feature": 8,
      "revision": 256,
      "interface": 1,
      "collection": 1,
      "name": "演示接收器",
      "protocol": "custom-read",
      "reader": {
        "mode": "get-feature",
        "report_id": 7,
        "match": [{ "offset": 1, "mask": 255, "value": 164 }],
        "level": { "offset": 2, "mask": 255, "shift": 0, "maximum": 100 },
        "status": {
          "offset": 3,
          "mask": 3,
          "charging": [1],
          "sleeping": [2],
          "offline": [3]
        }
      }
    }
  ]
}
```

偏移从 0 开始。第 0 字节是报告 ID，即使设备没有编号也保留为 0。示例中报文 `07a4480100000000` 符合特征字段，电量为 72%，状态为充电。电量先应用掩码和右移，再按 `maximum` 换算百分比。休眠和离线只在报文明确定义对应状态时显示。

自定义配置可以执行 GetFeature 或读取 Input 报告。要求先发送厂商 Output 命令、设置 Feature 报告、执行握手或校验复杂帧的型号，仍需为探测器增加专用适配。Windows 对输入、特性和输出报文使用不同的接口。 [Microsoft HID 报文读取说明](https://learn.microsoft.com/windows-hardware/drivers/hid/obtaining-hid-reports)
